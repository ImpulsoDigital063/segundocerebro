## Fracasso do dia · 8 aprendizados cravados

### 1. Picsum random foi cagada
Usei `picsum.photos/seed/X` como placeholder em PhotoPlaceholder.tsx pensando que "seed determinístico" garantiria neutralidade. Errado · picsum entrega foto aleatória (paisagem · retrato genérico · café com latte). Hero virou foto de praia · tobogã virou Homem-Aranha · piscina de bolinhas virou toca-discos. **Pior** que placeholder vazio porque destrói credibilidade premium ANTES do usuário ler uma frase.

→ Memory cravada: `feedback_nunca_picsum_random_em_lp_real`. Regra: LP de cliente real exige (a) foto curada cliente, (b) stock curado com query específica + URL fixa por slot validada, ou (c) placeholder tipográfico neutro. Nunca picsum/random.

### 2. Mascote antropomorfizado de objeto = uncanny valley garantido
Tentei "carretinha rosa com olhos e sorriso" Pixar-style no Flux 1.1 Pro. Saíram 2 imagens medonhas. Razão técnica: dar rosto humano a objeto inanimado tem armadilha cognitiva — o cérebro espera coerência (Cars sabe fazer · porque investiu décadas em proporções) e Flux 1.1 Pro com prompt curto entrega caricatura.

→ Funciona quando: personagem é uma PESSOA fictícia (astronauta Planeta Kids · super-herói Capitão Festa). Não funciona quando: humanizo um objeto industrial.

### 3. Premium editorial light = austero · "não diverte"
v2 e v3 começaram com Plus Jakarta Sans 300 / Bricolage 300 (light weight) em headlines. Visualmente premium e clean — mas Eduardo cravou: *"Verbo as fontes estão muito serias, não diverte"*. Tipografia premium pra adulto NÃO é fonte light · é boa hierarquia + peso adequado + personalidade. Bricolage 700 entrega alegria + premium. Bricolage 300 entrega banco de investimentos.

### 4. Pesquisar referências DESDE O COMEÇO encurta a entrega
Gastei 3 versões da LP (v1 cartoon chunky · v2 editorial austero picsum · v3 Aquarella). Cada uma teve que voltar parcial pra estaca zero. Se tivesse pesquisado as 5 referências NO DIA 1 (e auditado o Aquarella com CIC NO DIA 1), tinha entrado direto na v3. Lição: pesquisa não é "depois do MVP" · pesquisa é parte do briefing.

### 5. Foto real do cliente > qualquer stock
As 5-6 fotos do carretakids elevaram o visual da LP em uma escala que stock Unsplash nem com curadoria boa entregou. Mesmo sendo fotos de outro operador BR · contexto bate · credibilidade salta. **Pedido cravado**: quando o cliente NÃO tem pack pronto, isso é uma URGÊNCIA de briefing · não um "OK pra depois". Sem foto real, qualquer LP de serviço fica visualmente refém.

### 6. CIC não grava arquivo
O Claude for Chrome não tem acesso ao filesystem do PC. Quando o prompt pede "salve em X.md", ele entrega no chat e Eduardo cola pro Verbo salvar. **Atualizei** `reference_ferramentas_claude_eduardo.md` com essa limitação.

### 7. Replicate Flux 1.1 Pro é caro pra iterar conceito incerto
$0.04 por geração soa barato — mas com iteração de mascote uncanny, 5 tentativas viram $0.20 sem entrega. Lição: pra conceitos com risco alto de "achar que tá ruim", validar antes com Schnell ($0.003) ou desenhar referência manual. Pro só vale quando o conceito está claro.

### 8. Cravar feedback DURANTE conversa > cravar memória no fim do dia
Hoje cravei 3 memories durante a conversa: `feedback_nunca_picsum_random_em_lp_real`, `feedback_filtrar_recomendacoes_de_outros_agentes` (já existia mas reforcei), e atualizei `reference_ferramentas_claude_eduardo` com CIC limitação. Se tivesse esperado o fim do dia, perderia o contexto granular. Memory escrita perto do erro = memory útil.
