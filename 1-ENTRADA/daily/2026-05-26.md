# 26/05 · 🚨 P0 Olímpio booking quebrado · SECURITY DEFINER cravado · análise impacto antes prod

## 🚨 INCIDENTE DO DIA

**P0 PRODUÇÃO · Olímpio · clientes não conseguiam agendar há ~24h**

- Sintoma: cliente abre `/palmas-do-olimpio` · escolhe serviço/horário · clica "Agendar" · erro "Erro ao agendar"
- Quem reportou: Olímpio via WhatsApp · "tô perdendo cliente"
- Janela: ~24h antes do report · vários agendamentos perdidos

**Diagnóstico:**
- Trigger v70 `auto_create_invoice_for_appointment` rodava AFTER INSERT
- BookingFlow público faz INSERT como `anon`
- Trigger v70 INSERT em `invoices` + `invoice_items` → RLS bloqueava `anon`
- Erro silencioso · cliente via "Erro ao agendar" sem detalhe

**Fix (migration v77):**
```sql
CREATE OR REPLACE FUNCTION public.auto_create_invoice_for_appointment()
RETURNS TRIGGER
SECURITY DEFINER  -- ← este é o fix
SET search_path = public
AS $$ ... $$
```

`SECURITY DEFINER` faz a function rodar como owner do banco, NÃO como `anon`. RLS de invoices não aplica.

**Regra cravada (λ.trigger-security-definer):** trigger que toca tabela com RLS forte EXIGE `SECURITY DEFINER`. Sem isso, anon quebra.

**Tempo perdido:** ~24h de booking público quebrado · vários clientes Olímpio perdidos.

## Regra dura cravada (λ.analise-impacto-antes-de-prod)

Eduardo cravou após P0: **não posso quebrar prod nesse início**. Checklist 6 pontos OBRIGATÓRIO antes de migration/mudança crítica:

1. **Quem dispara?** (admin · anon · trigger DB · cron?)
2. **Tabelas tocadas** (e RLS dessas tabelas)
3. **Dado obrigatório** (NOT NULL · UNIQUE · default?)
4. **Fluxo prod** (cliente leigo / admin / cron sincroniza?)
5. **Rollback** (script reverso existe?)
6. **Cliente afetado** (alguém pagando? quanto? down ok?)

Sem passar pelos 6 · NÃO aplicar migration em prod.

Memory `feedback_analise_impacto_antes_de_prod` cravada.
