## O que foi feito

### 1. WhatsApp tab — reescrita completa

Contexto: aba de configuração que gera QR code pro cliente do estabelecimento apontar e cair direto no WhatsApp do dono. Antes era uma tela meia morta; agora é ferramenta real.

- Nova coluna `whatsapp_intro_message` em `businesses` (migration v24)
- Campo editável com autosave (debounce 800ms) — sem botão "Salvar", o cliente só digita
- Funções `formatPhoneBR()` e `buildPhoneForWA()` — trata prefixo "55" automaticamente
- **Web Share API** (`navigator.share`) com fallback pra clipboard — compartilha o link do agendamento nativo no celular
- **Impressão A5** — abre janela nova com QR SVG estilizado pra imprimir e colocar no balcão/recepção
- Empty state bonito com ícone WhatsApp custom + CTA pra preencher o telefone no painel Negócio
- Stepper visual de 4 passos (Imprima → Cole → Cliente aponta → Cai no WhatsApp)
- 6 pills de lugares sugeridos (Recepção, Espelho, Balcão, Vitrine, Cardápio, Caixa)

### 2. Lighthouse real na página pública

Rodei Lighthouse em `agendapro.net.br/teste-smoke-1` (negócio de teste em prod). Resultado:

- **Performance 68** (mobile)
- **LCP 12,8s** — ruim
- Causa raiz identificada: **UMA foto de profissional com 1.788 KB** representa 80% do payload total
- O resto do sistema é enxuto: 185 KB de JS+CSS+HTML, server response 30ms

Conclusão: **o sistema não é pesado, o problema é upload cru**. Se isso já machuca com 1 foto, multiplica por 10 profissionais.

### 3. Pipeline de compressão automática (preventivo, não corretivo)

Eduardo colocou a ficha: *"o cliente também vai querer colocar qualquer foto sem se preocupar com tamanho"*. Decisão: resolver no código, não no treinamento.

Criado `src/lib/compress-image.ts` com:

- 3 presets: `photo` (800px/250KB/WebP), `logo` (512px/150KB/WebP), `cover` (1600px/400KB/WebP)
- Lib `browser-image-compression` v2.0.2 rodando em web worker (não trava UI)
- Conversão automática pra WebP
- Hard limit 15 MB de entrada
- Rejeita HEIC
- Retorna `{ ok: true; file; originalKB; compressedKB }` ou `{ ok: false; reason }`

Aplicado em `ProfissionaisTab` (foto) e `NegocioTab` (logo). Qualquer upload novo deve usar o helper.

**Impacto real:** fotos de 5-10 MB viram ~250 KB WebP. Capacidade de Supabase Free vai de ~150 negócios para milhares.

### 4. Bottom nav — iteração que ensinou

**Primeira tentativa** — sombra aurora animada + pill central ativa. Eduardo reprovou: *"não curti muito, e o círculo azul fica desencaixado nos ícones e textos. esse é o design premium que você havia mencionado?"*

O diagnóstico certo era: a pill 52×38 engolia ícone + label abaixo dela. Aurora era sutil demais pra aparecer. Visualmente desconectado.

**Segunda tentativa — Capsule Material You (aprovada):**

- Inativo: ícone puro, label colapsada (`max-width: 0 → 140px`)
- Ativo: pill com ícone + label lado a lado, padding 14px → 18px, gradient + inset border + shadow
- Microbounce no tap (220ms cubic-bezier elastic)
- Haptic via `navigator.vibrate(8)`
- Badge vermelha "9+" cap pra contagem alta

Componente único `DockNav.tsx` em `src/components/admin/` usado por:

- `BottomNav` (admin) — tabs: Agenda, Clientes, Configurações. Badge combina `appointments.pending` + `review_claims.pending`
- `ProfissionalBottomNav` — tabs: Agenda, Horários, Financeiro, Conta (só "Agenda" + "Conta" se for contratado). Badge de appointments pendentes

Padding-bottom dos layouts subiu pra 108px (floating dock).

### 5. Hub Conta do profissional + bug da engrenagem

**Bug reportado pelo Eduardo:** criou acesso novo pra profissional, ele trocou a senha no primeiro acesso, entrou no painel. Ao clicar na engrenagem (aba Conta), voltou pra tela "crie uma nova senha" — **já tinha criado**.

Causa: `/profissional/trocar-senha` estava fora do route group `(protected)`, com copy hardcoded de "senha temporária". A engrenagem apontava pra lá.

**Correção:**

- Criado `/profissional/(protected)/conta/` — hub com 3 cards:
  1. Identidade (avatar com foto ou iniciais, nome, email, badge comissionado/contratado)
  2. Trocar senha (form expansível inline, posta no endpoint existente)
  3. Sair (logout + redirect)
- `/profissional/trocar-senha` virou server component com guard: se `password_changed=true`, redireciona pra `/conta`
- `TrocarSenhaForm` extraído pra client component (mantém fluxo de primeiro acesso)
- Bottom nav do profissional: engrenagem agora aponta pra `/conta`

## O que eu aprendi

### 1. Diagnóstico real > achismo

Antes de tocar em código de performance, Lighthouse. O dado mostrou que **o problema NÃO era o que parecia** — não é app pesado, é upload cru. Se eu tivesse otimizado JS/CSS no chute, perderia dias e não resolveria o gargalo real. Isso virou padrão: antes de "otimizar", medir. Antes de "simplificar", contar o que pesa.

### 2. Preventivo no código > treinamento no cliente

A decisão de compressão automática em vez de "avise o cliente pra comprimir" é o padrão certo. Cliente de barbearia não vai abrir TinyPNG — ele tira foto no celular, anexa, pronto. Qualquer fricção é perda. O código absorveu a responsabilidade. Regra: se depende de disciplina do usuário final, é bug de design.

### 3. Crítica direta é combustível, não grosseria

Quando Eduardo disse "não curti, ficou desencaixado" sobre o primeiro DockNav, se eu tivesse defendido o que fiz, teria perdido meio-dia. A resposta certa foi: reconhecer falha → propor 3 alternativas reais → ele escolhe. Velocidade de iteração depende de honestidade bruta de quem tá pedindo. Pra mim: traduzir "não curti" em "vamos reiniciar", nunca em "explica melhor o que quer".

### 4. Bug quase invisível é pior que bug visível

O bug da engrenagem voltando pra "trocar senha" não quebrava nada, não dava erro, não aparecia em log — só deixava o profissional confuso por 3 segundos. Bug silencioso é o que ninguém reporta mas todos sentem. Vale caçar esses mesmo sem ticket.

### 5. Hub Conta é padrão pra crescer sem bagunçar

Criar um `/conta` simples agora abre espaço pra foto, tema, dados pessoais, notificações — sem nenhum desses ter que sair do menu principal. Padrão: quando uma tela técnica (trocar senha) vira órfã, criar um hub temático pra onde ela pertence, e a órfã vira filha.
