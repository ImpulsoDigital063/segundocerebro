## 🏗 Conquistas (14 commits, 1391efc → 283283e + 41a3718)

### 1. PIX nativo no AgendaPRO (`6eb30fa`)
- Cliente paga PIX **dentro** do `/admin/bloqueado`, sem sair pro asaas.com
- `getPixQrCode()` adicionado em `src/lib/asaas.ts`
- `PixInlineCheckout.tsx` renderiza QR base64 + chave copia-cola + polling 5s
- Quando webhook PAYMENT_RECEIVED chega → polling detecta status='active' → router.refresh() → painel libera
- Resultado: 70% das vendas BR (PIX) viram experiência 100% AgendaPRO

### 2. Emails branded Resend (`e9618a2` + `41a3718`)
- Header gradient emerald (#10B981) → cyan (#06B6D4) com logo branco
- Rodapé com WhatsApp suporte + assinatura "Eduardo · AgendaPRO"

- Bug "Olá, Salão" corrigido (fallback usa email_localpart antes de business.name)

### 3. Cancel-asaas robusto (`1391efc`)
- **Bug raiz descoberto:** Asaas exige saldo INTEGRAL pra estornar PIX, mas cobra taxa antes de receber. R$67 venda → R$65,02 saldo → refund rejeitado por R$1,98 faltando.
- Antes: marcava cancelled mesmo com refund falhado (cliente em limbo)
- Agora: se ≤ 7d e refund FALHOU → não cancela DB, retorna 502, dispara email alerta pro Eduardo (sendRefundFailedAlert)
- Refund OK → marca refunded_at imediato (otimista, idempotente com webhook)
- Mensagem PlanoCard agora diferencia "reembolso solicitado · acesso encerrado" de "cancelado · usa até DD/MM"

### 4. Splash branded `/admin/loading.tsx` (`283283e`)
- Erlane reportou "10s tela branca" pós-cold-start Vercel
- Loading.tsx com logo + 3 dots pulsando substitui tela branca em transições
- Não cobre cold start completo (server hibernado) — backlog: service worker app shell

### 5. LP guard server-side (`a1ce9b2`)
- Erlane: "saí do /admin sem clicar, voltou pra LP"
- Causa: swipe-back iOS Safari pulou histórico pra LP visitada antes do cadastro
- Helper `redirectIfLoggedIn()` em 5 LPs (/, /barbearia, /salao, /estetica, /nail)
- Cliente logado com business → redirect pra /admin imediato

### 6. /cadastro guard (`0265a96`)
- Race condition pós-pagamento: webhook → polling → refresh → getCurrentBusiness retorna null transitório → redirect /cadastro → cliente cria business duplicado
- Fix: `getCurrentBusiness` com retry (.maybeSingle distingue 0 rows de erro)
- `/cadastro/layout.tsx` server-side: se user já tem business, redirect /admin
